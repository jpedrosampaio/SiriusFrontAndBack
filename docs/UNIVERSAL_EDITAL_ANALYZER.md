# Universal edital analyzer — structural maintenance

Authorized maintenance; not a new master-plan phase. Base audited: main `70de336c09b5f7f290103a3840afd978f827453a`. This document is a design/audit record, not a publication or real-provider validation claim.

## Proven causes and limits before architecture changes

- `server.process_edital_analysis` validates PDF bytes, then obtains a Gemini key before local extraction/cache. The initial request asks for all roles and their complete syllabuses in one bounded output. Hydration/re-enumeration repeats substantial context. Strict JSON/error handling published in PR52 prevents false success but does not remove the oversized-response architecture.
- The current queued path uses the same monolithic processor. `EditalJobs` starts only with configured object storage; otherwise the UI falls back to a long synchronous request. A running job whose lease expires becomes failed; validated intermediate semantic units do not exist.
- Reuse `EditalAnalysis` for owned document identity, hash, source text/pages, revisions and historical compatibility. Reuse the existing job orchestrator for background lifecycle; do not create another study planner, ownership system or AI registry.
- Current source/review/import consumers assume a completed all-role payload. Incremental inventory, selected-role work and unresolved evidence must be explicit contracts rather than a fake legacy completed analysis.
- Supplied local PDF: SHA-256 `1564d6ccacdb20b5b16ad77fa2ccfc667efb925f83ab4d9b75150ade8745039e`, 70 pages, 232713 characters with pypdf, no page below 50 extracted characters in the initial pass. The syllabus starts on page 50 under section 14; Annex I on page 67 is a schedule. Neither that page pattern nor any board/role count can be a product rule. This extraction-only audit does not prove semantic completeness or provider behavior.
- pdfplumber and pypdf are already declared dependencies. Local tesseract is unavailable in the audited environment: distinguish OCR-required pages from invalid/empty PDFs and block complete publication when required text is missing. Original PDF bytes are private local input and are not committed or redistributed.

Prototype extraction measurement on the supplied PDF (local Windows, not a production benchmark): 70 text pages, 229422 characters in word-based extraction, 2772 source blocks, 62 table rows and six two-column hints; supervised subprocess took 39.01 seconds. Comparing the alphanumeric character multiset **per page** against the independent pypdf extraction found zero unmatched/extra characters after NFKC/case normalization. This checks that metric only: it does not establish reading order, semantic completeness, correct roles/associations or model success. Layout hints still require semantic/human verification. Linux CPU/address-space limits and Windows input/page/output/deadline supervision have different guarantees; do not claim a Windows RLIMIT memory bound.

Dependency audit found the declared pdfplumber0.11.6/miner20250327 below the maintainer's patched20251230 minimum for [GHSA-wf5f-4jwr-ppcp](https://github.com/pdfminer/pdfminer.six/security/advisories/GHSA-wf5f-4jwr-ppcp) and [GHSA-f83h-ghpp-7wcc](https://github.com/pdfminer/pdfminer.six/security/advisories/GHSA-f83h-ghpp-7wcc). Before enabling new parsing, pin pdfplumber0.11.10/miner20260107 and pypdf6.20.1, whose [official release](https://github.com/py-pdf/pypdf/releases/tag/6.20.1) includes cyclic-tree protection. The initial measurement above predates this upgrade and must be renewed. The worker fails closed with an old miner. This is a dependency finding, not evidence of an incident/exploit in the supplied document. Use an isolated local environment; retain all CI gates and add parser dependencies to the existing regression workflow, without reducing its tests.

Renewed measurement with those exact patched versions, relative-font/paragraph hints and the same local file: 6.96 seconds; same70textpages/229422characters/2772blocks/62table rows and zero unmatched/extra alphanumeric characters per-page against the original pypdf baseline. These are two local runs, not a controlled performance benchmark or a production speed guarantee. Private intermediate output remains outside Git. Nine synthetic extraction/security/admission tests and nine pure semantic-gate tests passed; durable orchestration, provider simulations and product integration are not yet implemented/validated by those tests.

## Planned contracts and risks

1. Validate/extract in a bounded subprocess before provider access. Preserve page/block text, ordering, bounding boxes, table cells and recurring header/footer hints in a versioned intermediate representation. Heuristics are routing hints, never verified facts. Encrypted/corrupt/oversized/resource-limited and OCR-required inputs have different safe diagnostics.
2. Persist extracted input in PostgreSQL before acknowledging durable ingestion. Extracted text is resumable input, not durable original-PDF storage; the UI must not promise original download after restart. Hash/version dedup is account-scoped.
3. Discover inventory from bounded page/block batches independently from per-role depth. Preserve typed evidence with exact page/block excerpts, ambiguity and unknown values. Select a role before scheduling its detailed units; do not process every role's full syllabus up front.
4. Checkpoint independently typed small units. Reuse the existing queue with lease fencing, bounded retries/backoff, quota pause, cancellation, resumption and explicit per-document resource budgets. Never hold a SQL transaction during a provider call. Account → analysis → job/unit lock order; stale results cannot overwrite a changed/cancelled analysis or confirmed human corrections.
5. Consolidate deterministically by stable source identifiers. Keep shared/specific disciplines, topics/subtopics, stages and exam rules distinct. Group question counts/weights remain on their source group unless the document explicitly distributes them. Missing or contradictory coverage blocks complete/confirmed planning inputs.
6. Review/corrections are revision-checked, owned and audited; every confirmed field retains document or declared-human provenance. Reanalysis creates proposed evidence and does not silently replace confirmed edits. Prepare complementary-document relationships explicitly without treating a linked URL as authority or fetching arbitrary instructions.
7. Retain historical analyses/imports and the sole Global Planner. Adapt confirmed selected-role results to existing study consumers; incomplete work cannot establish a definitive plan. No document instruction gains authority over the user's request or server tools.
