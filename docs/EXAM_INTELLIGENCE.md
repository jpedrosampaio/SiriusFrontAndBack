# Phase 6 - Exams, Simulations & Final Sprint

Audit base: phase5 merge d0a0fd8b07e1c009e60676321b7864f213c26ab0, published on both providers; live/ready/frontend200. Questions Intelligence and Adaptive Strategy contracts were read before implementation.

Existing Exam/ExamQuestion/Question/ExamAttempt and QuestionAttempt already store owned questions, weights, historical results, confidence, changed answers and optional seconds. Submission uses the shared user lock/activity receipt and writes answers, review events and XP atomically. Blank answers remain facts but do not enter mastery. Existing blueprint assembly clones question rows, breaking canonical error-recovery identity; it labels all extracted counts as sourced without inspecting confirmation. The existing timer counts callbacks, loses progress on exit and never submits per-question seconds. EssayCorrection has owned JSON history but no official rubric verification and the provider runs before receipt replay.

Implementation contracts: reuse Exam.blueprint JSON for one bounded active execution per owned exam, with session UUID, revision/CAS and immutable completion receipt; final results remain append-only ExamAttempt. No new database model or migration. No progress save grants XP. Session finish shares the submission transaction, blocks duplicate completion across different keys and preserves legacy direct-submission APIs. Question assembly should link canonical Question IDs instead of cloning them, preserving provenance and error-bank identity. Recorded edital counts/weights must expose confirmed, extracted/unverified and unknown status; practice settings are user-defined, never inferred board rules. Unknown penalties default to ordinary weighted practice, not invented negative marking.

Post-mortem derives timing, confidence calibration, weighted points lost, blanks and repeat mistakes from stored facts, with explicit sample limits and no diagnosis or pass prediction. Individual answers continue to feed the existing PreparationState/mastery/review pipeline. Final Sprint is a read-only proposal using the same Strategy Engine candidates, with 90/30/14/7/2-day stages; no automatic deletion or calendar changes. Essay assessments are always estimated; optional user-provided criteria are labeled as such, never claimed official, and no real AI is used in tests.

Verification and final exact-head CI/review/production metadata are recorded in the PR and the current section of HANDOFF.md. Protected migrations workflow is required if schema scope changes; production Alembic is never run by the agent directly.

## Implementation and limits

Execution routes: GET/POST/PUT /api/study/simulados/{id}/session. PUT validates bounded typed answers, monotonic aggregate/per-question seconds, option membership, persistent changed-answer flags and exact revision. POST resumes active execution; a completed exam can start an explicit new execution. Final submit with session_id/revision grades only the saved snapshot, completes it and writes canonical evidence/XP in one transaction. Concurrent different receipts can complete it once; identical receipts replay. An active execution cannot be bypassed by legacy submission. Historical direct submissions without an active execution remain supported. Exam list/catalog responses exclude execution answers; the owned session endpoint returns them. One active session per exam, no server stopwatch claim: timing measures interaction on the visible page and pauses when hidden/paused. Autosave every5 seconds, save-and-exit awaits acknowledgment; abrupt termination can lose only unconfirmed edits. Network uncertainty retains exact request payload/key; stale-tab409 requires explicit reload. No test writes in production.

Blueprint modes: edital, discipline, topics, weak and quick (max10). Counts max200; selection max100 topics/disciplines. Bank reads deduplicate canonical question IDs before the10000-question limit, exclude inactive scopes, preserve provenance and link existing Question rows. Weak mode consumes the existing Strategy Engine ranking (unknown evidence remains unknown), not a new mastery system. Incomplete edital distribution is refused. Unverified data requires explicit provisional-practice confirmation. Quantity/weight source and status are visible. Official rules are not automatically verified. Default scoring remains all-question weighted practice. Nonzero wrong/blank penalties require a user-confirmed source plus excerpt; stored results preserve the exact rule, each question's net points and negative total points. Existing0-100 score remains a normalized percentage with floor0, explicitly distinct from raw points. Do not present this practice percentage as an official board score. Blank facts never enter mastery.

Post-mortem: weighted lost points, blanks vs wrong answers, recorded mean time by discipline/topic/type, relative per-question time budget, confidence groups, answer changes and same-canonical-question recurrence. No guessed error cause, calibrated pass probability or diagnosis. These answers feed existing QuestionAttempt/ReviewEvent/PreparationState; no duplicated evidence ledger. Attempt history is selectable; review-errors opens the existing performance/error bank.

Final Sprint is read-only and uses PreparationState's actual exam/meta date and the Strategy Engine priorities. Boundaries90/30/14/7/2 days propose fractions of existing available time for new content/questions/error review/simulations. Unknown/past/outside90 dates produce no percentage proposal. No deletion or protected-plan rewrite. Percentages are operational defaults, not measured optimal strategies.

Essay/discursive assessments retain existing EssayCorrection JSON history. Optional user criteria and kind are bounded; provider output scores must be finite and in their scales. Server labels every result estimated/nonofficial, stores rubric fingerprint/source, and reuses the existing durable provider reservation (short database transactions, no lock during AI). Same-key concurrent requests return a retryable in-progress409 or the saved result; no duplicate provider call/artifact/XP. Legacy clients without a key remain compatible but cannot obtain replay guarantees. Compare history only with matching rubric/scale; essays remain unlinked to preparations, never falsely changing topic mastery. All provider tests use mocks.

Schema unchanged, head a81c9d37e502. No production migration is necessary for phase6. Any subsequent schema change must use production-migrations and owner Environment approval.
